# Supplier Scope 3 Hotspot Tool

A small Python tool that turns a procurement spend extract into a supplier-level
Scope 3 footprint. It then shows where to engage suppliers to cut emissions.
I built it as a working example of the supplier GHG work that a corporate
sustainability team does with its Global Supply Management organisation.

**[Live dashboard →](https://claude.ai/artifact/BkkS5kf4xDhzFzCRtEaxG3)** (sample data)

## What it answers

1. **How large is our upstream footprint, and how sure are we?** Each supplier is
   estimated with the most specific method available under the
   [GHG Protocol Scope 3 Technical Guidance](https://ghgprotocol.org/scope-3-calculation-guidance-2)
   hierarchy. Every estimate gets a data-quality score and an uncertainty range.
2. **Where are the hotspots?** By category, by supplier, and how few suppliers
   make up 80% of the total.
3. **Who should we talk to first?** A ranked engagement list with concrete asks:
   PCF in PACT format, a science-based target, a renewable power plan.
4. **Will supplier action get us to a 1.5 °C path?** A 2025–2030 scenario model
   for renewable power, low-carbon materials and supplier targets. The dashboard
   has sliders for engagement coverage and business growth.

## Results on the sample data

| | |
|---|---|
| Upstream footprint | **46,461 tCO₂e** ± 4,016 (1σ) |
| Spend-based estimate alone | 37,872 tCO₂e (**18% too low**). Aluminium's real material intensity is much higher than its spend suggests |
| Suppliers covering 80% | 18 of 46 |
| Primary (supplier) data coverage | 5%; weighted DQ 3.3 |
| 2030 combined pathway | 34,525 t vs 36,704 t on a 4.2 %/yr linear 1.5 °C path |

The biggest single lever is data. 7 of the 18 largest suppliers are still
estimated from spend, so asking them for product carbon footprints would change
the picture the most.

## Method

| Method | Formula | DQ |
|---|---|---|
| Supplier-specific | kg purchased × supplier PCF | 1 (verified) / 2 |
| Average-data | kg purchased × industry-average factor | 3 |
| Spend-based | USD spent × EEIO factor | 4 |

* **Uncertainty**: ±10/20/30/50% (1σ) by DQ, combined as root-sum-square across suppliers.
* **Renewable power lever**: removes the electricity-related share of each
  category's footprint that is not yet renewable. It ramps linearly to 2030
  for suppliers within the engagement coverage.
* **Material switch**: 50% recycled aluminium (14 → 1.5 kgCO₂e/kg) and 50% EAF
  steel (2.0 → 0.7 kgCO₂e/kg) by 2030.
* **Supplier targets**: suppliers with SBTi targets cut 4.2%/yr. Engaged
  suppliers without a target adopt one from 2027.
* **Combined**: per supplier, the larger cut of (renewable power × materials) or
  its own target, so no tonne is counted twice.

> **Data note.** Suppliers are fictional and generated by
> `scripts/generate_sample_data.py` (seeded, reproducible). The emission factors
> in `data/emission_factors.csv` are illustrative placeholders of plausible
> magnitude. Replace them with USEEIO, EXIOBASE or ecoinvent values before
> relying on any number.

## Run it

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m scope3                       # sample data -> output/
.venv/bin/python -m scope3 --suppliers my.csv --coverage 0.9 --growth 0.03
.venv/bin/python -m pytest -q
```

Outputs in `output/`: `dashboard.html` (self-contained), `results.json`,
`supplier_emissions.csv`, `category_emissions.csv`, `scenarios.csv`,
`engagement_list.csv`. The CSVs load directly into Excel or Power BI.

### Input format (`suppliers.csv`)

| column | required | notes |
|---|---|---|
| supplier_id, supplier_name, country, category, spend_usd | yes | `category` must match a row in the factors file |
| quantity_kg | no | enables average-data or supplier-specific methods |
| supplier_pcf_kgco2e_per_kg, pcf_third_party_verified | no | supplier product carbon footprint |
| has_sbti_target, renewable_electricity_share | no | used by scenarios and engagement ranking |

## Project layout

```
scope3/calculate.py     calculation hierarchy, DQ scoring, uncertainty, aggregation
scope3/scenarios.py     reduction levers, 1.5 °C path, engagement ranking
scope3/__main__.py      CLI; writes CSV/JSON and renders the dashboard
dashboard/template.html dashboard (JS port of the scenario model; checked equal to Python)
data/                   sample suppliers + emission factors
tests/                  pytest suite
```
